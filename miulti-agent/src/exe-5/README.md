大分経過してしまいましたが、マルチエージェント強化学習(MARL)で前回から更新が止まっていた問題解決までトライアルです。
今回の問題設定について説明していきます。

## 問題設定
### 1. 問題の目的

本タスクは、**2体のエージェントが共有ターゲット地点に協調して到達する**ことを目的とするマルチエージェント強化学習（MARL）問題です。  
単に「各自が最短経路で動く」だけでは効率が悪く、**ボトルネック（狭い通路）や衝突回避を考慮した協調行動**が求められます。

**主目的**  
- 両エージェントができるだけ早く、かつ**同時に**共有ターゲットに到達すること  
- その過程で、**衝突や混雑を避けつつ、全体の移動効率を最大化**すること

### 2. 環境設定

__2.1 グリッドワールド__

- サイズ：`size × size` の2次元グリッド（例：5×5）  
- 各セルはエージェントの位置を表し、上下左右に移動可能。

__2.2 エージェント__

- 数：2体（Agent 0, Agent 1）  
- 初期位置：  
  - Agent 0: `(0, 0)`（左上）  
  - Agent 1: `(size-1, size-1)`（右下）  
- 行動：  
  - 0: 待機  
  - 1: 上  
  - 2: 下  
  - 3: 左  
  - 4: 右  

__2.3 ターゲット__

- 共有ターゲット：`(size-1, size-1)`（右下）  
- 両エージェントがこのセルに同時に到達することがゴール。

__2.4 ボトルネック（狭い通路）__

- 中央行（`size // 2`）に**1マス幅の通路**のみが存在し、それ以外のセルは通行不可。  
- 例：5×5グリッドの場合、中央行の中央列（`(2,2)`）のみ通行可能。  
- これにより、エージェントは**順番に通過する必要**があり、独立最適行動では渋滞が発生します。

__2.5 終了条件__

- 最大ステップ数に達する（例：30ステップ）  
- または、両エージェントが同時にターゲットセルに到達する

### 3. 観測（Observation）

各エージェントは以下の情報を観測します（正規化済み）：

- 自分の位置 `(x, y)`  
- ターゲットへの相対距離 `(Δx, Δy)`  
- 他エージェントとの相対位置 `(Δx_other, Δy_other)`  
- ボトルネック位置への相対距離 `(Δx_bn, Δy_bn)`  

これにより、エージェントは「自分とターゲットの関係」「他エージェントとの位置関係」「ボトルネックの位置」を認識できます。

### 4. 報酬設計（協調を促す要件）

__4.1 グローバル距離報酬__

- 両エージェントのターゲットまでの距離の合計に比例したマイナス報酬  
- 式：`-0.1 * (dist0 + dist1)`  
- 目的：**全体としてターゲットに近づく**ことを促す。

__4.2 同時到達ボーナス__

- 両エージェントが同時にターゲットに到達した場合、**大きな正の報酬（+5.0）**  
- 目的：**協調的なゴール達成**を強く評価する。

__4.3 衝突ペナルティ__

- 両エージェントが同じセルに同時に入ろうとした場合、**マイナス報酬（-1.0）**  
- 目的：**衝突回避**と「順番待ち」の学習を促す。

__4.4 混雑ペナルティ__

- ボトルネック付近で両エージェントが近づきすぎた場合、**マイナス報酬（-0.5）**  
- 目的：**間隔調整**（一方が待機し、他方が先に通過するなど）を促す。

### 5. マルチエージェントに求められる要件

__5.1 協調ナビゲーション能力__

- **経路の調整**：ボトルネックを通過する際、どちらが先に通るかを暗黙に決定する。  
- **タイミングの調整**：一方が待機し、他方が先に通過するなど、**時間的な協調**が求められる。

__5.2 衝突回避と混雑管理__

- 同じセルへの同時進入を避ける。  
- ボトルネック付近で過度に接近しないように間隔を保つ。

__5.3 部分観測下での意思決定__

- 各エージェントは「自分の位置・ターゲット・他エージェント・ボトルネック」の相対情報しか持たない。  
- これらを統合し、**他エージェントの意図を推測しながら行動**する必要がある。

__5.4 グローバル報酬の理解__

- 各エージェントは「自分の行動がチーム全体の報酬にどう影響するか」を学習する必要がある。  
- これはMAPPOやQMIXなどの**集中学習・分散実行（CTDE）** アルゴリズムが得意とする部分です。

### 6. まとめ

この問題設定は、**単純なナビゲーションタスクに「ボトルネック」「衝突」「同時到達ボーナス」を加えることで、協調行動を強く要求するMARLベンチマーク**として設計されています。  
エージェントは、単に最短経路を選ぶだけでなく、

- どちらが先にボトルネックを通るか  
- どのタイミングで待機・前進するか  
- どのように衝突を避けるか  

を**分散的に学習**する必要があります。

## 解法

上記の協調ナビゲーション環境を解くためのマルチエージェント構成を、アルゴリズムの観点から整理します。


### 1. 環境の特徴（アルゴリズム選択の前提）

環境の主な特徴は以下です。

- **グローバル報酬**：距離の合計・同時到達ボーナス・衝突ペナルティなど、**チーム全体の報酬**が中心。  
- **部分観測**：各エージェントは自分の位置・ターゲット・他エージェント・ボトルネックの相対情報のみを持つ。  
- **協調が必要**：ボトルネックや衝突回避のため、「順番待ち」「間隔調整」などの**協調行動**が不可欠。  
- **エージェント数が少ない**：2エージェントなので、大規模分散型よりも**集中型・通信型**の手法が適しやすい。

この環境は「**協調ナビゲーション＋グローバル報酬＋部分観測**」という、典型的なCTDE（Centralized Training, Decentralized Execution）向きのタスクです。


### 2. 解決に選定したアルゴリズム

例のごとくQMIX系（Value Decomposition）による解法を検討します。

**概要**  
- グローバルQ値を「各エージェントのQ値の混合」として表現し、**集中学習・分散実行**を行う。  
- 代表例：QMIX, VDN, QPLEX など。

**この環境への適合性**  
- グローバル報酬（距離の合計・同時到達ボーナス）を**価値分解**で扱える。  
- 部分観測から各エージェントがローカルQ値を学習し、Mixing Networkが協調構造を学習する。  
- 2エージェントなので、Mixing Networkもシンプルで済む。

**構成案**  
- 各エージェント：DQN（またはRNN-DQN）でローカルQ値を学習。  
- Mixing Network：グローバルQ値を出力し、**単調性制約**（QMIX）で分解を保証。  
- 入力：各エージェントの観測（位置・ターゲット・他エージェント・ボトルネック）＋必要に応じて状態情報。

**メリット**  
- グローバル報酬を自然に扱える。  
- 分散実行が可能（学習時だけ集中情報を使う）。  
- 協調構造（順番待ち・間隔調整）をMixing Networkが暗黙に学習。

**デメリット**  
- 価値ベースなので、連続行動や確率的方策には不向き（この環境は離散行動なので問題なし）。  
- 通信プロトコルを明示的に学習しない（暗黙の協調に依存）。
