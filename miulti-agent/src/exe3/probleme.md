**情報共有と継続的な協調**に焦点を当てた、別の代表的な協調型MARLの例題として、**「複数のセンサーによる災害現場の探索（Multi-Sensor Search & Coverage）」** を問題として考えてみました。


## 協調的な例題：複数のセンサーによる災害現場の探索 (Multi-Sensor Search & Coverage)

この例題は、限られた観測範囲を持つ複数のエージェントが、**情報不足の中で知識を共有**し、**協力して未探索エリアを効率的にカバーする**という、協調的な意思決定を学ぶのに適しています。

### 設定

* **環境:** 災害により情報が遮断された未知のグリッドマップ。マップ上には救助対象者や危険区域などの**目標（Target）**が隠されています。
* **センサー（観測）:** 各ドローン（エージェント）の観測範囲は非常に狭く、隣接するマスしか見ることができません。

### エージェントと目標

| **項目**               | **詳細**                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| **エージェント**       | 複数台の探索ドローン（または移動式センサーロボット）。                              |
| **行動（アクション）** | 上、下、左、右への移動、待機。                                                      |
| **目標**               | **マップ全体を最も早く、効率的に探索し終える** （未探索エリアを最小化する）。 |

### 相互作用と学習のポイント

この例題における「協調」と「難易度」のポイントは以下の通りです。

#### 1. 情報の共有と分散的知識 (Distributed Knowledge)

* **協調の必要性:** 各ドローンが個別に探索したエリアの情報を**共有**しなければ、他のドローンが同じ場所を何度も探索してしまう（重複探索）という非効率が発生します。
* **学習目標:** エージェントは、観測した情報を**共通のグローバルな知識マップ（共有メモリや通信） **に統合・反映し、その知識に基づいて** 「まだ誰も行っていない場所」**へと向かう戦略を学習します。

#### 2. 全体カバレッジの最適化 (Optimal Coverage)

* **競合 vs 協調:** フォークリフト問題が**「衝突を避ける」 **というネガティブな協調（競合回避）だったのに対し、本例題は** 「未探索エリアを分担する」**というポジティブな協調が中心です。
* **学習目標:** ドローン群が互いに**適切な距離**を保ち、密集しすぎず、離れすぎず、**協力して探索エリアを分割**するような、空間的な負荷分散戦略を学習します。

#### 難易度と基礎学習

この問題は、タスクの完了（ピックアップ/ドロップオフ）が明確でなく、報酬設計が「未探索マス数」の減少という**スパース（まばら）な報酬**になりやすいため、Q-Learningなどの基礎的な手法を適用する際の**状態表現と報酬設計の難しさ**を学ぶのに適しています。

特に、**通信チャネル**や**共有知識の表現方法**を設計・導入することで、純粋な協調学習（集中制御、分散実行など）の基礎を学ぶことができます。

## `MultiSensorSearchEnv` の構成と役割

このクラスは、複数のドローン（エージェント）が未知のグリッドマップを探索するシミュレーション環境を提供しています。

### 1. 初期設定 (`__init__` 部分)

環境の物理的なパラメータと初期状態を定義します。

| 要素 | 説明 | 役割 |
| :--- | :--- | :--- |
| **`GRID_SIZE`** | マップの一辺の長さ。 | 環境の大きさの定義。 |
| **`NUM_AGENTS`** | ドローン（エージェント）の数。 | 協調問題の規模を決定。 |
| **`SENSOR_RANGE`** | ドローンが一度に見える範囲（例: 1なら周囲3x3）。 | **部分観測性** (Partial Observability) の設定。 |
| **`explored_map`** | **探索状態マップ** (`numpy.zeros`)。 | **共有知識**。どのマスが探索済みか（1）未探索か（0）をチーム全体で共有するメモリの役割を果たします。 |
| **`action_space`** | 5 (待機、上、下、左、右)。 | エージェントが取りうる行動の定義。 |


## 環境のライフサイクルとコアメソッド

### 2. 環境のリセット (`reset` メソッド)

エピソードの開始時に環境を初期状態に戻します。

* `self.explored_map` を全て `0` (未探索) にクリアします。
* 各エージェントの現在位置 (`self.agent_positions`) をマップ上のランダムな場所に再配置します。
* 初期位置に基づいて、初期の探索エリアを `_update_exploration()` で即座に反映します。

### 3. 状態の取得 (`_get_obs` メソッド)

現在の環境状態（観測）を、各エージェントが学習に使える形式で返します。

* 返される観測 (`obs`) は、各エージェントIDに対応する辞書です。
* 各エージェントは、**自分の現在位置** (`position`) と、チームが共有する**グローバルな探索済みマップ** (`map`) を観測として受け取ります。

### 4. 探索エリアの更新 (`_update_exploration` メソッド) 💡 **協調学習の核心**

エージェントが移動した結果、**新しく**探索されたマスを計算し、マップを更新します。

* 各エージェントの位置を中心に `SENSOR_RANGE` の範囲を計算します。
* その範囲内のマスを見て、**`explored_map` が `0` のマス（未探索）**であれば、それを**新規発見**としてカウントし、マップを `1` に更新します。
* このメソッドが返す `newly_explored_count` が、直後の**報酬計算**に利用されます。

### 5. ステップ実行 (`step` メソッド)

エージェント群の行動を受け取り、環境を1ステップ進めます。

1.  **移動の実行**:
    * 各エージェントの行動に基づき、次の座標を計算します。
    * マップの境界外への移動は `np.clip` により防止されます。
2.  **報酬の計算**:
    * 各エージェントに **`-0.1`** の**タイムペナルティ**（短い時間での完了を奨励）を与えます。
    * `_update_exploration()` で得られた `new_cells` に基づき、**チーム全体**に**協調報酬** (`team_reward`) を分配します。これは、**重複探索を避けて広範囲に散らばる行動**を学習させるための重要な設計です。
3.  **終了判定 (`done`)**:
    * 探索率が **`1.0` (100%)** に達したか、または最大ステップ数 (`MAX_STEPS`) に達した場合にエピソードを終了します。
    * 100% 達成時にはボーナス報酬が与えられます。
