## 問題

先程の倉庫を協調して解く問題ですが、２つのエージェントのうち、片方だけが動作する。

## 原因調査

倉庫環境での協調学習において、片方のエージェントだけが働いてしまう現象は、マルチエージェント強化学習（MARL）では非常に有名な**「怠惰なエージェント（Lazy Agent）問題」**と呼ばれるものです。

QMIXのような集中学習・分散実行（CTDE）の手法では、チーム全体の報酬を最大化しようとするあまり、効率化の過程で「一人が頑張り、もう一人は邪魔をしないように止まっている」という状態が最適解として学習されてしまうことがあります。

原因と具体的な解決案を整理しました。

---

### 1. なぜ片方しか動かないのか（原因分析）

1. **報酬の割り当て問題（Credit Assignment）:**
   チーム全体の報酬（Global Reward）のみを与えている場合、Agent Aの行動によって報酬が得られたのか、Agent Bの行動のおかげなのかをネットワークが正確に判断できず、最初に成功体験を得た片方のエージェントの重みだけが更新され続けることがあります。
2. **「邪魔をするリスク」の回避:**
   衝突ペナルティがある場合、慣れないうちは動くとぶつかって報酬が減るため、「動かずに待機しているほうが、チーム全体の報酬（マイナスを避けるという意味で）に貢献する」と学習してしまいます。
3. **観測情報（Observation）の不足:**
   各エージェントが「相方が今どこにいて、何をしようとしているか」を知らない場合、同じ荷物を狙って効率が悪くなるのを避けるため、片方が譲ってしまう現象が起きます。
4. **探索不足:**
   学習の初期段階で片方のエージェントが偶然タスクを達成してしまうと、そちらのQ値が急速に高まり、もう一方のエージェントが「正解」を見つける前に探索（Epsilon）が終わってしまうことがあります。

---

### 2. 解決案：協調を促すためのアプローチ

#### A. 報酬設計の改善（Reward Shaping）

全体の報酬だけでなく、**個人の貢献**や**移動コスト**を導入します。

* **移動ペナルティの導入:**
  何もせず止まっているよりも、目標に向かって進むことにインセンティブを与えます。
* **個別報酬（Partial Individual Reward）:**
  「荷物を拾った瞬間」や「目標に近づいた瞬間」に、そのエージェント個別の小さな報酬を与えます。
* **待機ペナルティ:**
  「荷物を持っていない、かつ移動もしていない」時間に微小なペナルティを与えます。

#### B. 観測情報（Observation）の強化

エージェントが互いを認識できるようにします。

```python
# 修正案：観測に「相方の位置」を含める
def _get_obs(self) -> Dict[int, Tuple]:
    obs = {}
    for i in range(self.num_agents):
        other_agent_idx = 1 - i # 2エージェントの場合
        obs[i] = (
            self.agent_positions[i],      # 自分の位置
            self.agent_holding[i],        # 自分の状態
            self.agent_positions[other_agent_idx], # 相方の位置（重要！）
            tuple(self.remaining_orders)  # 残りの注文
        )
    return obs

```

#### C. QMIXのミキシングネットワークの調整

片方のエージェントのQ値に依存しすぎないよう、ネットワーク構造や学習率を調整します。

* **学習率（Learning Rate）を下げる:** 急激な収束を防ぎ、両方のエージェントに探索の機会を与えます。
* **Epsilonの減衰をより遅くする (`EPS_DECAY` を大きくする):** 片方が成功しても、もう片方が試行錯誤を続ける時間を長く確保します。

---

### 3. 具体的なコード修正例（報酬関数）

環境クラス `WarehouseEnv.step` 内の報酬計算を以下のように「協調を促す形」に変更することを推奨します。

```python
def step(self, actions: Dict[int, int]) -> Tuple[Dict, Dict, Dict, Dict]:
    # ... 移動処理 ...

    rewards = {i: 0.0 for i in range(self.num_agents)}
  
    for i in range(self.num_agents):
        # 1. 共通のベース報酬（時間経過によるマイナス）
        rewards[i] -= 0.01 
      
        # 2. 荷物を拾った/届けた時の個別報酬
        # (ここで individual_achievement などのフラグを判定)
        if picked_up_this_step[i]:
            rewards[i] += 0.5  # 拾った本人へのボーナス
      
        if delivered_this_step[i]:
            rewards[i] += 2.0  # 届けた本人へのボーナス

    # QMIXには「チーム全体の報酬（和）」を渡す
    # しかし、個別のボーナスが含まれているため、両方が動く動機になる
    return next_obs, rewards, done, info

```

### 💡 次のアクションとして

まずは、**「各エージェントの観測（Observation）に、相方の位置を含める」** 修正を行ってみてください。これにより「相方が右の荷物を狙っているから、自分は左へ行こう」という戦略（協調行動）が学習可能になります。

### 倉庫問題を解くための次のステップ案

もし倉庫問題を解決したい場合、以下のようなアプローチを試してみるのはいかがでしょうか？

* **Curriculum Learning (カリキュラム学習):** 最初は **$3 \times 3$** の極小の倉庫から始め、学習が進むにつれてサイズを大きくしていく。
* **Reward Shaping (報酬整形):** 荷物を届けるだけでなく、「荷物との距離が縮まったら少しプラス」という報酬を与える。
* **Action Masking (アクション・マスキング):** 壁にぶつかる行動や、明らかに無駄な行動をネットワークが選ばないように制限をかける。
