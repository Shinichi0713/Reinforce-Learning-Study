## 初回実装方針

MARLの問題を解くときに特に効果が大きかったのがTransformerで構築して、位置エンコーディングにRoPEを適用した時でした。
今回もベースとなるニューラルネットワークは[RoPE](https://yoshishinnze.hatenablog.com/entry/2026/08/06/043000)で実装を進めていきます。

今回のドローン配送MARL実装は、**「空間的な状況把握にTransformerを使い、複数ドローンが協調して荷物を配送する方策をMAPPOで学習する」** という構成で実装していきます。

### 1. 全体の設計思想：CTDE（Centralized Training Decentralized Execution）
強化学習の思想は[CTDE](https://yoshishinnze.hatenablog.com/entry/2025/11/18/053506)に基づきます。

複数エージェントの学習で最も重要なのが、**「学習時は全員の情報を使って賢くなり、実行時は各ドローンが自分だけの情報で動く」** という設計です。

| フェーズ | Actor（方策） | Critic（価値評価） |
|---|---|---|
| **学習時（Training）** | 自分の観測から行動確率を出力 | **全エージェントの観測を統合**して「この状況は良いか悪いか」を評価 |
| **実行時（Execution）** | 自分の観測だけで行動選択 | 不要（推論時はActorのみ使用） |

これにより、ドローン同士の衝突回避や荷物の分担を学習しつつ、実際の運用では通信不要の分散制御が実現できます。

### 2. 観測表現：グリッドを「画像」のように扱う

ドローンの観測を、10×10のグリッドを**6チャンネルの画像データ**としてTransformerに入力して実装していきます。

```
チャンネル0: 自分の位置      (One-Hot)
チャンネル1: 相手の位置      (One-Hot)
チャンネル2: 未回収の集荷地点 (One-Hot)
チャンネル3: 未配達の配達地点 (One-Hot)
チャンネル4: 自分が持つ荷物の目的地
チャンネル5: 相手が持つ荷物の目的地
```

**なぜこれが重要か：**  
強化学習では「状態の捉え方」が性能を大きく左右します。座標のリストではなくグリッド画像にすることで、**Transformerが「右に3マス先に荷物がある」といった空間的な関係性を直接学習**できるようになります。

### 3. 2D RoPE（Rotary Position Embedding）：空間の「相対位置」をAttentionに組み込む

通常のTransformerは「1次元の並び」しか扱えませんが、今回は**2D RoPE**を使ってグリッドのx座標とy座標の回転をQuery・Keyに直接適用していきます。

**直感的なイメージ：**  
各グリッドセル（トークン）に対して、「自分は(2,3)にいる」「隣のセルは(2,4)だ」という**相対的な位置関係**を回転行列でエンコードします。これにより、Attentionスコアが「近くのセルほど強く注目する」という空間的な帰納偏倚を自然に獲得します。

**絶対位置エンコーディング（Sin-Cos）との違い：**  
絶対位置は「(2,3)という場所の特徴」を学習しますが、RoPEは **「右に1マス、上に2マス」のような相対的な距離感**を内積Attentionに直接組み込むため、未知のグリッドサイズへの外挿も容易です。

### 4. Action Masking：無意味な行動を物理的に禁止する

ドローンが「荷物を持っていないのにDeliver（配達）を選ぶ」や「壁の外に移動しようとする」といった**無効な行動**を確率0にします。

```python
# 例：荷物を持っていない → Deliverの確率を-inf（0%）に
logits = logits.masked_fill(action_mask == 0, float('-inf'))
```

**効果：**  
- 学習初期の「意味のない行動に固まる」という**方策崩壊（Policy Collapse）を防ぐ**
- 探索空間を物理的に正しい範囲に限定し、サンプル効率を向上

### 5. MAPPOの学習メカニズム

__A. GAE（Generalized Advantage Estimation）：「どの行動が良かったか」を評価__

Actor-Criticモデルに基づく実装を行います。このため報酬の安定化のため、行動評価に[GAE](https://yoshishinnze.hatenablog.com/entry/2026/07/24/043000)を用います。
各ステップで、「実際に得た報酬」と「Criticが予測した価値」の差分から**アドバンテージ（Advantage）** を計算します。

```
良い行動  →  Advantage > 0  →  その行動の確率を増やす
悪い行動  →  Advantage < 0  →  その行動の確率を減らす
```

※割引率は`λ=0.95` を使うことで、将来の報酬を考慮しつつもバイアスと分散のバランスを取ります。

__B. PPO-Clip：方策を「壊さず」に更新__

行動の確率を変えすぎると、以前のデータ（ロールアウト）が無意味になります。[PPO](https://yoshishinnze.hatenablog.com/entry/2026/08/10/043000)は**クリップ率 ε=0.2** で更新幅を制限し、「信頼領域内で少しずつ改善」を保証します。

```
新しい方策 / 古い方策 が 0.8～1.2 の範囲を超えたら、そこで勾配を切る
```

__C. Entropy Bonus：探索の多様性を維持__

方策が早期に「常に上へ進む」など1つの行動に固まるのを防ぐため、行動確率の**エントロピー（乱雑さ）を報酬として加算**します。今回は `entropy_coef=0.05` とやや高めに設定し、十分な探索を促進しています。

### 6. 報酬設計と学習安定化の工夫

| 工夫 | 目的 |
|---|---|
| **距離報酬（0.05×距離に応じた報酬）** | 目標へ近づくたびに小さなプラス報酬を与え、スパースな報酬（集荷・配達時のみ）を補完 |
| **報酬クリッピング（±10）** | 異常な大きさの報酬が価値関数を破壊するのを防ぐ |
| **Criticの学習率を高く設定（1e-3）** | 価値関数をActorより速く正確に学習させ、Advantageの精度を向上 |
| **100エピソードごとのチェックポイント** | 学習の途中経過を保存し、最高性能のモデルを `checkpoint_best.pth` として保持 |

### 7. 今回実装のまとめ

```
┌─────────────────────────────────────────────┐
│  観測：グリッド画像（6ch）で空間構造を保持      │
│      ↓                                      │
│  特徴抽出：2D RoPE Transformerで相対位置を学習  │
│      ↓                                      │
│  行動選択：Action Maskで無効行動を排除         │
│      ↓                                      │
│  学習：CTDE-MAPPOで協調行動を最適化            │
│      ↓                                      │
│  安定化：GAE + PPO-Clip + Entropy + 報酬設計   │
└─────────────────────────────────────────────┘
```

この構成により、各ドローンが **「自分がどこにいるか」「荷物はどこか」「相手がどこに向かっているか」** をTransformerのAttention機構で空間的に理解し、衝突を避けながら効率的に荷物を集荷・配達する協調行動を獲得することを目指していきます。

### 1. まず全体像：何を作ったか

今回作ったのは、大きく分けて **3つの部品** からなるプログラムです。

| 部品 | 役割 | イメージ |
|---|---|---|
| **配送シミュレータ（環境）** | ドローンが動く仮想の街を作る | ゲームの世界 |
| **ドローンの頭脳（Transformer）** | 今の状況を見て「どこへ行くか」を決める | ドローンの運転手 |
| **教官（MAPPO学習アルゴリズム）** | ドローンの行動を評価して、賢くなるように鍛える | 運転の教官 |

この3つが連携して、ドローンたちが「荷物を効率よく届ける」方法をゼロから学んでいきます。

### 2. 環境：ドローンが動く「仮想の街」

10×10のグリッド（マス目）の上に、以下が配置されています。

- **ドローン2台**（青とオレンジ）
- **荷物3個**（それぞれ「集荷地点（赤）」と「配達地点（緑）」を持つ）
- **最大200ステップ**の制限時間

ドローンは1ステップごとに以下の行動から1つ選びます。

- 移動（上・下・左・右）
- その場で待機
- 荷物を拾う（Pick）
- 荷物を届ける（Deliver）

**報酬（褒美・ペナルティ）の設計：**
- 荷物に近づく → 小さなプラス
- 荷物を拾う → +1
- 荷物を届ける → +10
- 全荷物配達完了 → +5
- ドローン同士が衝突 → -5

この「報酬」を最大化しようとするのが、ドローンたちの目標です。

### 3. 頭脳：Transformerで「空間の意味」を理解する

ドローンが賢く動くためには、「自分の位置」「相手の位置」「荷物の位置」の関係を理解する必要があります。

__観測を「画像」のように見る__

今回、ドローンの目に映る情報を **10×10の6チャンネル画像** のように表現しました。

```
チャンネル1: 自分がどこにいるか
チャンネル2: 相手ドローンがどこにいるか
チャンネル3: まだ拾っていない荷物はどこか
チャンネル4: まだ届けていない配達先はどこか
チャンネル5: 自分が持っている荷物の目的地
チャンネル6: 相手が持っている荷物の目的地
```

これにより、ドローンは「地図」を見て判断できるようになります。

__2D RoPE（回転位置エンコーディング）__

通常のTransformerは文章（1次元）向けですが、今回は**2次元の地図**を扱うため、「2D RoPE」という技術を使いました。

簡単に言うと、**「右に2マス、上に3マス先に荷物がある」** という**相対的な距離感**を、Attentionの計算に直接組み込む仕組みです。

これにより、ドローンは「近くの荷物を優先的に見る」「遠くの情報も適度に参照する」といった空間的な判断が自然にできるようになります。

### 4. 教官：MAPPOで「協調行動」を学習させる

複数のドローンが同時に学習するため、**MAPPO（Multi-Agent PPO）** というアルゴリズムを使います。

__なぜ「協調」が難しいか__

1台なら簡単ですが、2台になると以下の問題が起きます。

- 同じ荷物を両方が狙う
- 経路が被って衝突する
- 相手の動きを予測しないと効率が悪い

__CTDE（中央集権学習・分散実行）__

この問題を解決するために、以下の方式を採用しました。

| フェーズ | 内容 |
|---|---|
| **学習時** | 教官（Critic）は「全ドローンの位置と荷物の状態」を一度に見て、「この状この状況は良いか悪いか」を正確に評価 |
| **実行時** | 各ドローン（Actor）は「自分が見える範囲の情報だけ」で独立に判断 |

これにより、**学習時は協調の構造を理解しつつ、実際の運用では通信なしで自律飛行できる**という利点があります。

__PPO-Clip：壊れないように慎重に学習__

強化学習では、「新しい知見に急に乗り換えすぎる」と以前の良い行動を忘れてしまいます。PPOは **「今までの行動から大きく外れない範囲で、少しずつ改善する」** 制限をかけることで、安定した学習を実現します。

### 5. 学習を安定させる工夫

今回の実装では、学習がうまく進むよう、いくつかの工夫を入れています。

| 工夫 | 効果 |
|---|---|
| **Action Masking** | 壁の外に出たり、荷物を持っていないのに「配達」したりする無意味な行動を物理的に禁止 |
| **Entropy Bonus** | ドローンが「常に上へ進む」など1パターンに固まらないよう、探索を促進 |
| **GAE（一般化アドバンテージ推定）** | 「この行動が良かったか」を、将来の報酬も含めて正確に評価 |
| **報酬クリッピング** | 異常な大きさの報酬が価値関数を破壊するのを防ぐ |
| **チェックポイント保存** | 100エピソードごとにモデルを保存。最高性能のモデルを自動で保持 |

### 6. 実行の流れ

1. **シミュレーション開始**：ランダムな初期位置でドローンと荷物が配置される
2. **行動選択**：各ドローンがTransformerで地図を見て、次の行動を決める
3. **報酬獲得**：荷物を拾ったり、目的地に届けたりするとプラス報酬
4. **教官の評価**：MAPPOが「この行動は良かったか」を計算
5. **パラメータ更新**：Transformerの重みが少しずつ賢くなるように調整
6. **繰り返し**：5000エピソード繰り返し、協調配送のスキルを磨く

最終的に、学習済みのドローンは以下のような行動を学習します。

- 近くの荷物を効率よく拾う
- 相手ドローンと衝突しないよう経路を調整
- 自分が持つ荷物の目的地へ最短で向かう

## 総括

以下、今回のドローン配送MARLトライアルの結果を簡潔にまとめます。

### 1. やったこと

### 3. 何が効いたか

| 技術 | 効果 |
|---|---|
| **2D RoPE Transformer** | グリッド上の「相対的な距離感」をAttentionに直接組み込めたため、空間的な状況把握が劇的に向上 |
| **CTDE** | 学習時にCriticが全エージェントの情報を統合して評価したことで、協調行動（衝突回避・荷物の分担）が自然に獲得できた |

### 4. わかったこと・教訓

- **Transformer（特にRoPE）は、マルチエージェントの空間的な意思決定に非常に強力**。従来の線形結合層と比較して、「どこに何があるか」の関係性を構造的に理解できるため、MARLの複雑な協調タスクにもあっさり適応した。
- **観測表現（グリッド画像化）が重要**。座標の羅列ではなく、地図としてTransformerに入力することで、空間的な推論が可能になった。
- **Action Maskingは必須に近い**。物理的に不可能な行動を排除することで、探索空間を大幅に絞り、学習の安定性と速度が向上した。
- **CTDEは「協調」を学ばせる上で有効**。各ドローンが独立に動きつつも、学習時に全体最適を意識した価値評価ができた。

### 5. 所感
今回のトライアルで、**「Transformer（2D RoPE）+ MAPPO + CTDE + Action Masking」** という構成が、ドローン配送のような空間的・協調的なMARLタスクに対して非常に有効であることが確認されました。特に、過去のPursuitタスクで得た「RoPE Transformerの強さ」が、より複雑な配送問題でもそのまま活きたことが大きな知見となりました。
