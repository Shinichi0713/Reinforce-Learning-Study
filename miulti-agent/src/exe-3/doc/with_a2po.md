## 実装内容

A2POは比較的新しいMARL手法なので、正確な定義を確認してから実装します。A2POを探しました。これは2023年ICLR論文「Order Matters: Agent-by-agent Policy Optimization」(Wang et al.) で提案された、エージェントを順番に（agent-by-agentに）更新していく信頼領域法です。主な要素は次の3つです。

1. **Preceding-agent Off-Policy Correction (Pre-OPC)**：先に更新した（preceding）エージェントの方策変化を、Retrace風の打ち切り重要度サンプリングで補正したアドバンテージ推定
2. **Semi-greedy agent selection rule**：|アドバンテージ|が大きいエージェントを優先しつつ、一定確率でランダム選択する更新順序決定
3. **Adaptive clipping parameter**：更新順位 k に応じてクリップ幅を徐々に広げる

実装可能です。ただし論文は「単一の共有報酬」を前提とするDEC-MDPで理論構築されていますが、今回の環境は個人報酬+チーム報酬のハイブリッド設計なので、**各エージェント個別の報酬・価値関数に対してPre-OPCを適用する実務的な拡張**として実装します（この適応についてはコード内に明記します）。

まず環境・モデルの共有構造を確認し、A2POの学習ループを新規ファイルとして実装します。動作検証のため、小さな設定で数エピソードだけ実行し、エラーが出ないか確認します。この環境ではネットワークアクセスが無効化されており、PyTorchをインストールして実際に実行検証することができませんでした（`pip install torch` が失敗します）。構文チェック（`py_compile`）は通過しており、テンソルの形状・インデックス操作についても手計算で入念に確認済みですが、**お手元の環境で実行して動作確認してください**。念のため、最初の実行では `MAX_STEPS` や `A2PO_STAGES` を小さくして数エピソードだけ流し、エラーが出ないことを確認することをおすすめします。## 実装の要点

**`multi_agent_search_mappo_fixed.py` と同じフォルダに置いて実行してください**（環境・モデルをそのままimportして使っています）。

### A2POの3つの核心要素

1. **Pre-OPC（preceding-agent off-policy correction）**：すでに更新したエージェント（preceding agents）の方策変化を、Retrace(λ)風の打ち切り重要度サンプリング `c_t = min(1, 先行エージェントの同時確率比)` でアドバンテージ推定に織り込みます。`preceding` が空集合の最初の更新では `c=1` となり、通常のGAEと一致します。
2. **Semi-greedy agent selection rule**：各ステージで、残っているエージェントの中から確率 `SEMI_GREEDY_PROB`（デフォルト0.5）でランダムに、それ以外は `|advantage|` 平均が最大のエージェントを選んで更新します。
3. **Adaptive clipping parameter**：更新順位 `k` が後になるほどクリップ幅を `C(ε,k) = ε·c + ε·(1−c)·(k/n)` で広げます（論文は全タスクで `c=0.5` を使用）。

### パラメータ共有の扱い

本モデルはもともと1回のforwardで全エージェント分のlogits/valueを出す共有ネットワークなので、論文のAlgorithm 2（parameter sharing版）と自然に対応します。preceding agentの方策変化は、共有パラメータの更新が逐次反映される形でそのまま表現されます。

### 計算コストの注意

1エージェント更新ごとに「現在の方策を全timestepで評価（no_grad）」＋「勾配ありの更新パス」を行うため、既存のMAPPOより重くなります。`A2PO_STAGES = 2` をデフォルトにしていますが、学習が遅い・メモリが厳しい場合はここを1に下げてください。逆により多くの更新を試したい場合は増やせます。
