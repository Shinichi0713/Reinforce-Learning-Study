ボクシング（`boxing_v2`）環境の詳細な仕様について解説します。自作のMAPPOを実装する上で、入力（Observation）の形や出力（Action）の意味、そして報酬設計を把握することは非常に重要です。

---

### 1. 観測空間 (Observation Space)
デフォルトでは、Atariの生の画面データが返されます。

- **形式**: `Box(0, 255, (210, 160, 3), uint8)`
- **内容**: 210x160ピクセルのRGB画像です。
- **自作実装時の注意**: 
  - このままではMAPPOの入力として大きすぎ、また「色の情報」はボクシングの勝敗にあまり直結しません。
  - 通常は **(84, 84, 1)** へのリサイズとグレースケール化を行い、さらに動きを検知するために過去数フレームをスタックした **(84, 84, 4)** などの形状に変換してNN（CNN）に入力します。



---

### 2. 行動空間 (Action Space)
各エージェントは **18種類** の離散的な行動（Discrete）を持っています。これはAtari 2600のジョイスティックの全方向とボタンの組み合わせに対応しています。

| 番号 | 行動 | 意味 |
| :--- | :--- | :--- |
| 0 | `NOOP` | 何もしない |
| 1 | `FIRE` | パンチ |
| 2 | `UP` | 上に移動 |
| 3 | `RIGHT` | 右に移動 |
| 4 | `LEFT` | 左に移動 |
| 5 | `DOWN` | 下に移動 |
| 6-9 | `UP + 方向` | 斜め移動 |
| 10-18 | `BUTTON + 方向` | 移動しながらパンチ、またはガード |

- **ポイント**: 実際には18個すべてを使わなくても勝てるため、学習を早めるためにアクション空間を「前後上下＋パンチ」の数種類に削減（Action Reduction）する手法もよく取られます。

---

### 3. 報酬設計 (Rewards)
ボクシングの報酬は非常にシンプルかつ明確です。

- **パンチ成功**: 相手にパンチを当てると **+1**
- **被弾**: 相手からパンチを受けると **-1**
- **勝利**: 最終的に100発当てるか、制限時間終了時にスコアが多い方が勝ち。

**MAPPOにおけるポイント:**
MAPPOでは「集中クリティック」を用いるため、エージェント1の報酬だけでなく、エージェント2の報酬（-1 * エージェント1の報酬）も同時に評価し、ゼロサムゲームとしての価値を学習させることができます。

---

### 4. 終了条件 (Termination)
以下のいずれか一方で環境が終了します。

- **ノックアウト**: どちらかのスコアが **100** に達した時。
- **タイムアップ**: ゲーム内のタイマー（ステップ数）が上限に達した時。

---

### 5. エージェントの識別子
PettingZooのボクシング環境には2人のエージェントが存在します。

- `first_0`: 1P（通常、左側の白いボクサー）
- `second_0`: 2P（通常、右側の黒いボクサー）

自作のMAPPOを作る際は、これら2つのエージェントの観測を一つの `Critic` に入力し、それぞれの行動を決定する `Actor` を用意する構成になります。



---

### 自作実装へのアドバイス
この環境は「相手との距離」と「パンチを打つタイミング」がすべてです。
自作MAPPOを組む場合、まずは **「集中クリティックに何を渡すか」** を検討してみてください。単に2枚の画像を並べる（Concatenate）だけでも機能しますが、両者の座標（ピクセル情報から抽出したもの）を補助情報として渡すと、学習が劇的に早まることがあります。
