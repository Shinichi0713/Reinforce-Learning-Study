
GANやMAVENを学習すると **潜在空間（latent space）** という言葉がキーワードになります。
初めての場合、とっつきづらい言葉です。今日はそんなとっつきづらさを解消したいと思います。

## 概要
潜在空間とは、**観測データの背後にある「本質的な構造」を表す低次元の空間**のことです。


### 1. 潜在空間の直感的なイメージ

例えば「人の顔写真」を考えます。

- 生データ（ピクセル）の次元はとても大きい（例：100×100×3 = 30,000次元）
- しかし、顔の本質的な特徴は
  - 性別
  - 年齢
  - 髪の色
  - 表情
  - 顔の輪郭
  など、**もっと少ないパラメータ**で表せます。

この「本質的なパラメータの集合」が張る空間が**潜在空間**です。

- 生データ空間：高次元で冗長（似た顔でもピクセルは大きく違う）
- 潜在空間：低次元で意味的（似た顔は近いベクトルになる）


### 2. 潜在空間の利用例

<img src="image/README/marl_agent_adventure.gif" alt="jssp-3" width="500px" height="auto">

1. **次元削減（圧縮）**
   - 高次元データを低次元で表現できるため、計算コストやメモリを節約できます。
   - 例：PCA（主成分分析）は、データを「分散が大きい方向」に射影した低次元空間を作ります。

2. **意味的な表現**
   - 潜在空間上の近さが「意味的な近さ」に対応するように学習できます。
   - 例：顔画像の潜在空間では、「笑顔の顔」同士が近くに集まる。

3. **生成モデルでの利用**
   - 潜在変数 `z` をサンプリングし、デコーダで画像を生成する（VAE, GAN など）。
   - 潜在空間上を移動すると、生成される画像が滑らかに変化します。

4. **強化学習での探索の多様化（MAVENなど）**
   - 潜在変数 `z` を変えることで、エージェントの探索方略（ポリシー）を多様化できます。
   - 異なる `z` が「異なる探索モード」に対応し、協調パターンなどを見つけやすくします。


### 3. 具体例

#### 例1：PCA（主成分分析）
- データを「分散が大きい方向」に射影した低次元空間が潜在空間です。
- この空間上でデータを表現すると、元の情報をできるだけ保ちつつ次元を減らせます。

#### 例2：オートエンコーダ（Autoencoder）
- エンコーダ：入力 `x` → 潜在表現 `z`
- デコーダ：潜在表現 `z` → 再構成 `x'`
- `z` が潜在空間上の点で、`x` の「要約」になっています。

#### 例3：VAE（Variational Autoencoder）
- 潜在変数 `z` を確率分布（通常はガウス分布）からサンプリング
- 潜在空間上を少し動かすと、生成される画像が連続的に変化（例：笑顔→無表情→怒り顔）

#### 例4：MAVEN（Multi-Agent Variational Exploration）
- 各エピソードやタイムステップごとに潜在変数 `z` をサンプリング
- `z` が「どのような探索方略を取るか」を決める役割を果たし、探索の多様性を高める


## なぜ潜在空間が必要?

潜在空間が MAVEN や GAN で使われる理由は、**「探索や生成の多様性を、低次元で制御しやすくするため」** です。

### 1. 潜在空間の基本的な役割

- 生データ（画像のピクセル、エージェントの観測など）は高次元で冗長
- 潜在空間は、その背後にある**本質的なパラメータ**を低次元で表現した空間
- 潜在変数 `z` を少し動かすと、生成されるもの（画像・方略）が滑らかに変化

→ 潜在空間を使うと、**「何を変えるか」を低次元でコントロールできる**という利点があります。


### 2. MAVEN で潜在空間を使う理由

MAVEN（Multi-Agent Variational Exploration）は、**マルチエージェント強化学習における探索の多様化**を目的とした手法です[NeurIPS 2019](https://arxiv.org/abs/1910.07483)。

__なぜ潜在空間を使うか__

1. **探索方略の多様化**
   - 各エピソードやタイムステップごとに潜在変数 `z` をサンプリング
   - `z` が「どのような探索方略を取るか」を決める
   - 例：
     - `z1` が大きい → 積極的に未知の行動を試す
     - `z2` が大きい → 協調行動を重視する
   - 異なる `z` が**異なる探索モード**に対応し、協調パターンなどを見つけやすくなる

2. **連続的で滑らかな探索**
   - `z` を連続空間からサンプリングするため、探索方略が滑らかに変化
   - ランダム行動だけでは見逃しがちな「中間的な探索パターン」も試せる

3. **集中学習・分散実行（CTDE）との相性**
   - 学習時は全エージェントの情報を使って潜在空間を学習
   - 実行時は各エージェントが自分の観測と共有された `z` に基づいて行動
   - これにより、**協調的な探索**を実現しつつ、実行は分散的に行える

→ MAVEN では、潜在空間を使って**「探索の仕方そのもの」を多様化し、協調タスクを効率的に解く**ために使われます。


### 3. GAN で潜在空間を使う理由

GAN（Generative Adversarial Network）は、**生成モデル**として潜在空間をよく使います。

__なぜ潜在空間を使うか__

1. **生成の制御性**
   - 潜在変数 `z` を入力として、ジェネレータが画像を生成
   - `z` を少し変えると、生成される画像が滑らかに変化（例：笑顔→無表情→怒り顔）
   - これにより、**「どのような画像を生成したいか」を潜在空間上で指定**できる

2. **多様なサンプルの生成**
   - 潜在空間からランダムに `z` をサンプリングすることで、多様な画像を生成可能
   - 潜在空間が「データ分布の本質的な構造」を捉えていれば、そこからサンプリングするだけで自然な画像が得られる

3. **潜在空間の操作（StyleGAN など）**
   - より高度な GAN（例：StyleGAN）では、潜在空間をさらに分解し、
     - 顔の向き
     - 髪の色
     - 表情
     など、**意味的な属性ごとに制御**できるようにする
   - これにより、「この顔を笑顔にしたい」といった編集が可能になる

→ GAN では、潜在空間を使って**「生成の多様性と制御性」を実現する**ために使われます。


### 4. MAVEN と GAN の共通点・違い

__共通点__

- **低次元での制御**：高次元の出力（画像・方略）を、低次元の潜在変数でコントロール
- **多様性の確保**：潜在変数を変えることで、出力のバリエーションを生み出す
- **連続的な変化**：潜在空間上を滑らかに動かすと、出力も滑らかに変化

__違い__

- **MAVEN**：探索方略（ポリシー）の多様化 → 「どう探索するか」を潜在空間で制御
- **GAN**：生成画像の多様化 → 「どんな画像を生成するか」を潜在空間で制御


### 5. まとめ

- **潜在空間**は、高次元データの背後にある「本質的な構造」を低次元で表現した空間
- **MAVEN**では、潜在空間を使って**探索方略を多様化**し、協調タスクを効率的に解く
- **GAN**では、潜在空間を使って**生成画像の多様性と制御性**を実現する

どちらも、「潜在空間という低次元のハンドルを回すことで、高次元の複雑な振る舞い（探索・生成）を制御する」という発想で設計されています。

## 実験

以下は、**2次元潜在空間から画像を生成する簡易デコーダ**を作り、潜在空間上の点 `z=(z1, z2)` を動かしたときに画像がどう変わるかを可視化する Python コードです。

- 潜在空間：2次元（`z1, z2`）
- デコーダ：`z` から「色付き円」の画像を生成
- 可視化：潜在空間をグリッド状にスキャンし、各点に対応する画像を並べて表示

__実装コード（潜在空間の可視化）__

```python
import numpy as np
import matplotlib.pyplot as plt
from matplotlib.animation import FuncAnimation
from IPython.display import HTML

def decoder(z):
    """
    簡易デコーダ：潜在変数 z=(z1, z2) から「色付き円」の画像を生成
    - z1: 円の中心x座標（-1〜1 → 0〜画像幅）
    - z2: 円の中心y座標（-1〜1 → 0〜画像高）
    - 色: z1, z2 から計算（R,G,B）
    """
    img_size = 64
    img = np.zeros((img_size, img_size, 3))  # RGB画像

    # zを画像座標にマッピング
    cx = int((z[0] + 1) / 2 * img_size)
    cy = int((z[1] + 1) / 2 * img_size)
    radius = 10

    # 色をzから決める（簡易的に）
    r = (z[0] + 1) / 2  # 0〜1
    g = (z[1] + 1) / 2
    b = 1.0 - (r + g) / 2
    color = np.clip([r, g, b], 0, 1)

    # 円を描画（簡易版：ピクセル単位）
    for y in range(img_size):
        for x in range(img_size):
            if (x - cx)**2 + (y - cy)**2 <= radius**2:
                img[y, x] = color

    return img

def plot_latent_space_grid(n_samples=10):
    """
    潜在空間をグリッド状にスキャンし、各点の画像を並べて表示
    """
    z1_range = np.linspace(-1, 1, n_samples)
    z2_range = np.linspace(-1, 1, n_samples)

    fig, axes = plt.subplots(n_samples, n_samples, figsize=(12, 12))
    for i, z2 in enumerate(z2_range):
        for j, z1 in enumerate(z1_range):
            z = np.array([z1, z2])
            img = decoder(z)

            ax = axes[i, j]
            ax.imshow(img)
            ax.set_xticks([])
            ax.set_yticks([])
            if i == n_samples-1:
                ax.set_xlabel(f"z1={z1:.1f}", fontsize=8)
            if j == 0:
                ax.set_ylabel(f"z2={z2:.1f}", fontsize=8)

    plt.suptitle("潜在空間 z=(z1, z2) をグリッド状に動かしたときの画像変化", fontsize=16)
    plt.tight_layout()
    plt.show()

def animate_latent_walk():
    """
    潜在空間上を円運動する点 z の軌跡と、そのときの画像をアニメーション表示
    """
    fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(10, 5))

    # 潜在空間のプロット用
    ax1.set_xlim(-1.2, 1.2)
    ax1.set_ylim(-1.2, 1.2)
    ax1.set_xlabel("z1")
    ax1.set_ylabel("z2")
    ax1.set_title("潜在空間上の点 z の軌跡")
    ax1.grid(True)

    # 画像表示用
    ax2.set_title("デコーダが生成する画像")
    ax2.set_xticks([])
    ax2.set_yticks([])

    # アニメーション用のフレーム数
    n_frames = 100
    theta = np.linspace(0, 2*np.pi, n_frames)

    def update(frame):
        ax1.clear()
        ax2.clear()

        # 潜在空間上の点 z を円運動させる
        t = theta[frame]
        z1 = np.cos(t)
        z2 = np.sin(t)
        z = np.array([z1, z2])

        # 潜在空間上に点と軌跡を描画
        ax1.set_xlim(-1.2, 1.2)
        ax1.set_ylim(-1.2, 1.2)
        ax1.set_xlabel("z1")
        ax1.set_ylabel("z2")
        ax1.set_title("潜在空間上の点 z の軌跡")
        ax1.grid(True)

        # 過去の軌跡を薄く表示
        for i in range(frame):
            t_prev = theta[i]
            z1_prev = np.cos(t_prev)
            z2_prev = np.sin(t_prev)
            ax1.plot(z1_prev, z2_prev, 'o', markersize=3, color='blue', alpha=0.3)

        # 現在の点を強調
        ax1.plot(z1, z2, 'ro', markersize=8)
        ax1.text(z1+0.1, z2+0.1, f"z=({z1:.2f},{z2:.2f})", fontsize=10)

        # デコーダで画像を生成して表示
        img = decoder(z)
        ax2.imshow(img)
        ax2.set_title("デコーダが生成する画像")
        ax2.set_xticks([])
        ax2.set_yticks([])

    anim = FuncAnimation(fig, update, frames=n_frames, interval=200, repeat=True)
    plt.close(fig)
    return HTML(anim.to_jshtml())

if __name__ == "__main__":
    # 1. 潜在空間グリッドの可視化
    print("潜在空間グリッドの可視化（z1, z2 を動かしたときの画像変化）")
    plot_latent_space_grid(n_samples=8)

    # 2. 潜在空間上を動く点のアニメーション（Colabで表示）
    print("潜在空間上を円運動する点 z のアニメーション")
    anim_html = animate_latent_walk()
    display(anim_html)
```

__コードのポイント__

1. **簡易デコーダ `decoder(z)`**
   - 入力：2次元潜在変数 `z = (z1, z2)`（各要素はおおよそ -1〜1）
   - 出力：64×64 の RGB 画像
   - `z1, z2` から
     - 円の中心座標
     - 円の色（R,G,B）
   を決め、画像上に円を描画します。

2. **潜在空間グリッドの可視化 `plot_latent_space_grid`**
   - `z1` と `z2` を -1〜1 の範囲で均等にサンプリング
   - 各 `(z1, z2)` に対応する画像を格子状に並べて表示
   - 潜在空間上の位置が少し変わるだけで、画像（円の位置・色）が滑らかに変化する様子がわかります。

3. **潜在空間上の動きのアニメーション `animate_latent_walk`**
   - 潜在空間上で点 `z` を円運動させ、その軌跡と対応する画像をリアルタイムに表示
   - 潜在空間上を滑らかに動くと、生成される画像も連続的に変化することを視覚的に確認できます。

__実行イメージ（Google Colab）__

1. 上記コードをセルに貼り付け実行
2. まずグリッド状の画像が表示され、「z1, z2 を変えると画像がどう変わるか」が一目でわかる
3. 次にアニメーションが表示され、潜在空間上を動く点 `z` に応じて画像が変化する様子を確認できる

この例では「色付き円」という単純な画像ですが、

- VAE や GAN では、潜在空間から「顔画像」や「風景画像」を生成
- MAVEN では、潜在空間から「探索方略（ポリシー）」を生成

というように、**潜在空間が「本質的なパラメータの空間」として機能している**ことをイメージする助けになります。

## 総括
本説明を総括すると以下となります。
- 潜在空間は複数のパラメータを別の空間にマッピングして、本質的な情報に絞るという意味を持つ
- 本質空間は、実空間の中の特徴的な除法を有していて、本質空間の変化でアウトプットを制御できる
- 用途は様々(MAVENとGANでは異なる)
