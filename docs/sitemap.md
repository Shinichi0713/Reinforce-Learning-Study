# サイトマップ

## 🚀 Google Search Consoleにサイトマップを登録するメリット

Google Search Console（旧称：Google Webmaster Tools）に**サイトマップ**を登録することは、ウェブサイトの**検索エンジン最適化（SEO）**において非常に重要です。

サイトマップを登録すると、主に以下のようになります。

---

### 1. 🔍 クロールの効率化と促進

Googleのクローラー（Googlebot）は、基本的にリンクを辿ってウェブサイトを探索します。しかし、サイトマップを登録することで、クローラーに対してサイト内の全ての重要なページの「地図」を直接提供できます。

* **新しいページの発見** : サイト内に新しく公開したページや、既存のページから内部リンクが少ない（または全くない）ページを、クローラーに**迅速かつ確実**に知らせることができます。
* **大規模サイトの効率化** : ページ数が非常に多い大規模なサイトや、コンテンツが頻繁に更新されるサイトでは、クローラーが効率的にサイト全体を巡回（クロール）し、**重要な変更を見逃さない**ために役立ちます。

### 2. 📝 インデックス登録の促進

サイトマップに記載されたページは、Googleがインデックスに登録するための候補となります。

* **見落としの防止** : 内部リンク構造が複雑な場合や、特定のページが階層の深い位置にある場合でも、サイトマップによってそのページの存在が保証され、Googleにインデックス登録される可能性が高まります。
* **最終更新日の伝達** : サイトマップ（XML形式）には、各ページの最終更新日（`<lastmod>`タグ）を含めることができます。これにより、クローラーは**どのページが更新されたか**をすぐに知ることができ、再クロールの優先度を上げることができます。

---

## 📈 Search Consoleでの確認・診断機能

サイトマップを登録することで、Google Search Consoleの機能を使ってウェブサイトの状態をより詳細に**把握・診断**できるようになります。

### 3. 📊 パフォーマンスのトラッキング

登録したサイトマップを通じて、Googleがどのページをクロールし、インデックスに登録したか、そしてそれらのページが検索結果でどの程度のパフォーマンスを発揮しているかを追跡できます。

* **インデックスカバレッジの確認** : サイトマップに記載されているページの総数に対し、実際にGoogleにインデックス登録されたページ数を確認し、インデックス登録のエラー（例：クロール拒否、重複コンテンツなど）を特定できます。
* **統計情報の取得** : クロール頻度、クロールエラー、サーバー負荷に関する情報を確認でき、サイトの技術的な健全性を監視できます。

### 4. 🚨 エラーの特定と修正

サイトマップの処理中にGoogleが問題を発見した場合、Search Console上で通知されます。

* **URLエラーの報告** : サイトマップ内のリンク切れ（404エラー）や、Googleがクロールまたはインデックス登録できない技術的な問題（例：`noindex`タグの誤用）が発見された場合、具体的なURLとともにレポートされます。これにより、迅速に修正作業を行うことができます。

---

### ⚠️ 注意点

サイトマップの登録は、 **インデックス登録を保証するものではありません** 。

Googleは、サイトマップをあくまで「ヒント」として使用します。ページの内容が低品質であったり、Googleのガイドラインに違反していたりする場合、サイトマップに登録されていてもインデックス登録されないことがあります。

サイトマップは、あくまで**「Googlebotの効率的なナビゲーター」**として機能し、サイトのSEO的な健全性を高めるための重要なツールです。

# サイトマップの作り方

サイトマップ（XML Sitemap）の作り方は、使用しているウェブサイトの環境や、手動で作成するかツールを使うかによって異なります。

最も一般的な**3つの作成方法**と、サイトマップの**基本的な構造**について説明します。

---

## 1\. サイトマップの基本構造

サイトマップは、検索エンジン向けにサイトのURLを一覧化した**XML形式のファイル**です。主要なタグは以下の通りです。

| XMLタグ          | 意味                            | 必須/任意 | 説明                                                   |
| :--------------- | :------------------------------ | :-------- | :----------------------------------------------------- |
| `<urlset>`     | ファイル全体を囲むタグ          | 必須      | XMLファイルの開始と終了を示す                          |
| `<url>`        | 個々のURLに関する情報を含むタグ | 必須      | サイト内の1つのページを示す                            |
| `<loc>`        | ページのURL                     | 必須      | ページの絶対URL（`https://...` から始まる完全なURL） |
| `<lastmod>`    | 最終更新日                      | 任意      | ページの最終更新日時（例:`2025-11-15`）              |
| `<changefreq>` | 更新頻度                        | 任意      | ページの更新頻度（`daily`, `weekly` など）         |
| `<priority>`   | 優先度                          | 任意      | サイト内での重要度（0.0～1.0）                         |

### サイトマップの例

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
   <url>
      <loc>https://example.com/</loc>
      <lastmod>2025-11-15</lastmod>
      <changefreq>daily</changefreq>
      <priority>1.0</priority>
   </url>
   <url>
      <loc>https://example.com/about/</loc>
      <lastmod>2025-11-01</lastmod>
      <changefreq>monthly</changefreq>
      <priority>0.8</priority>
   </url>
</urlset>
```

---

## 2\. サイトマップの具体的な作成方法

サイトの規模や環境に応じて、以下のいずれかの方法を選びます。

### A. CMS（WordPressなど）のプラグイン/機能を使う (推奨)

WordPressなどの\*\*CMS（コンテンツ管理システム）\*\*を利用している場合、これが最も簡単で確実な方法です。

1. **SEOプラグインの導入**: **Yoast SEO**、**All in One SEO Pack**、または**XML Sitemaps**などのプラグインをインストールします。
2. **自動生成**: これらのプラグインの多くは、設定を有効にするだけで、新しいページが公開されたり、既存のページが更新されたりするたびに、サイトマップを**自動で生成・更新**してくれます。
3. **場所の確認**: 通常、サイトマップは `https://your-domain.com/sitemap.xml` のような固定URLに生成されます。このURLをGoogle Search Consoleに登録します。

### B. オンライン生成ツールを使う

静的なHTMLサイトなど、CMSを使っていない小規模なサイト向けの方法です。

1. **生成ツールの利用**: 「サイトマップ 生成 ツール」などで検索し、オンラインのXMLサイトマップジェネレーターにアクセスします。
2. **URLの入力**: サイトのURLを入力し、ツールにサイトの全ページをクロールさせます。
3. **ファイルのダウンロード**: ツールが生成した `sitemap.xml` ファイルをダウンロードします。
4. **アップロード**: ダウンロードした `sitemap.xml` ファイルを、サイトの**ルートディレクトリ**（ドメイン直下）にアップロードします。

### C. 手動で作成する

ページの増減がほとんどない非常に小規模なサイト向けの方法です。

1. **テキストエディタで作成**: 上記の**基本構造**に従って、メモ帳などのテキストエディタでXMLファイルを作成します。
2. **URLの正確な入力**: `<loc>` タグには、インデックス登録したいページの完全なURLを**一つずつ**正確に入力します。
3. **XMLファイルとして保存**: ファイル名を `sitemap.xml` として保存します。
4. **アップロード**: サイトの**ルートディレクトリ**にアップロードします。

---

## 3\. サイトマップの登録と設定手順

サイトマップファイルが作成できたら、最後に以下の手順でGoogleにその存在を伝えます。

### 1\. robots.txtへの追記

サイトのルートディレクトリにある **`robots.txt`** ファイルに、サイトマップの場所を追記します。これにより、Googlebotが見つけやすくなります。

```
Sitemap: https://your-domain.com/sitemap.xml
```

### 2\. Google Search Consoleへの登録

1. **Google Search Console** にログインし、該当するプロパティ（ウェブサイト）を選択します。
2. 左側のメニューから **「サイトマップ」** をクリックします。
3. **「新しいサイトマップの追加」** 欄に、サイトマップファイルのパス（例: `sitemap.xml`）を入力し、**「送信」** ボタンを押します。
4. Googleがサイトマップを処理し、エラーがないかを確認します。数日後、**「ステータス」** が **「成功しました」** になっていれば登録完了です。



Googleのクローラー（Googlebot）に確実に `robots.txt`ファイルを見てもらうためには、ファイルを**ウェブサイトのルートディレクトリ（最上位のディレクトリ）**に配置する必要があります。

これは、`robots.txt`の発見に関するGoogleの技術的な要件です。

---

## 📂 `robots.txt`の正しい配置場所

`robots.txt`ファイルは、サイトの**ドメイン名（ホスト名）の直下**に配置されなければなりません。

### ✅ 正しい配置例

ウェブサイトが `https://www.example.com` の場合:

1. **プロトコル** : `http://` または `https://`
2. **ホスト名** : `www.example.com`
3. **パス** : `/robots.txt`

ファイルへの完全なURLは以下のようになります。

`https://www.example.com/robots.txt`

### ❌ 間違った配置例

以下の場所では、Googlebotは `robots.txt`を認識しません。

* `https://www.example.com/subfolder/robots.txt`
* `https://www.example.com/files/robots.txt`

> 💡 サブドメインの場合:
>
> サブドメインを使用している場合（例: https://blog.example.com）、そのサブドメインごとに独立したrobots.txtファイルがルートディレクトリに必要です。
>
> * `https://blog.example.com/robots.txt`

---

## 🛠️ 配置後の確認手順

ファイルをルートディレクトリにアップロードした後、以下の手順でGooglebotが正しく読み取れているかを確認できます。

### 1. ブラウザでの確認

ウェブブラウザのアドレスバーに、あなたのドメイン名に `/robots.txt` を付けたURL（例: `https://your-domain.com/robots.txt`）を入力し、ファイルの内容が正しく表示されることを確認します。

### 2. Google Search Consoleの利用 (推奨)

Google Search Consoleの**「設定」 **セクションにある** 「クロールの統計情報」**で、Googlebotが `robots.txt`を最後に読み込んだ日時や、読み込みに成功したかどうかを確認できます。

また、**「カバレッジ」 **レポートや** 「サイトマップ」**レポートで、`robots.txt`によってクロールがブロックされているURLに関する情報を得ることができます。

**`robots.txt`は、ウェブサイトのSEOとクローラー管理の基本中の基本となるファイルです。** 正しい場所に配置することが、指示を有効にするための最初のステップとなります。
