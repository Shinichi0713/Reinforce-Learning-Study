# Google Colabのデバッグ

Google Colabには、エラーの原因を特定するための強力なデバッグツールがいくつか用意されています。初心者から上級者まで、使いやすい順に解説します。


## 1. ビジュアルデバッガ（GUI）を使う

現在、Colabにはもっとも直感的な**GUIデバッガ**が組み込まれています。

* **使い方:**
  1. コードセルの左端（行番号のすぐ左）をクリックして、**赤い丸（ブレークポイント）**を付けます。
  2. セルの右上にある「歯車アイコン」の隣、あるいはメニューの「表示」から「 **デバッガ** 」を有効にします。
  3. または、実行ボタンの右にある小さな虫のアイコンをクリックします。
* **メリット:** 変数の中身を一覧で確認したり、1行ずつ実行（ステップ実行）したりすることが、マウス操作だけで可能です。


## 2. マジックコマンド `%debug` を使う

コードがエラーで止まってしまった直後に、**「なぜ止まったのか」**を調べるのに最適です。

* **使い方:**
  1. エラーが発生したセルの直後に、新しいセルを作り **`%debug`** とだけ入力して実行します。
  2. 「ipdb」という対話型デバッガが起動します。
  3. 入力欄に変数名を入れるとその時の値が表示され、`u`（上へ移動）や `d`（下へ移動）でエラー箇所の前後の状況を確認できます。
* **終了方法:** `q`（quit）を入力して実行します。

---

## 3. `breakpoint()` 関数を使う（標準的な方法）

特定の場所でプログラムを一時停止させたい時に便利です。Python 3.7以降の標準機能です。

* **使い方:**
  **Python**

  ```
  def calculate_sum(a, b):
      result = a + b
      breakpoint()  # ここで実行が止まり、デバッグモードに入る
      return result
  ```
* **実行:** これを書いたセルを実行すると、その行で停止し、変数の値を確認できるプロンプトが表示されます。

---

## 4. 自動デバッグモード `%pdb on`

エラーが起きたら**自動的に**デバッガを起動させる設定です。

* 使い方:
  セルの冒頭に %pdb on と書いて実行しておくと、その後にエラーが発生した際、手動で %debug と打たなくても即座にデバッグ状態になります。

---

## 5. ログ出力（printデバッグ）の強化

デバッガを使うまでもない時は、`print()` を使いますが、Colab（Jupyter）では以下のツールも便利です。

* **`logging` モジュール:** 処理の経過を記録する。
* **`ic()` (icecream):** `pip install icecream` で利用可能。`ic(variable)` と書くだけで、変数名と値を綺麗に表示してくれるので、`print` よりも効率的です。

---

### おすすめの使い分け

* **「どこがおかしいか全く不明」** → 1のビジュアルデバッガで1行ずつ確認。
* **「エラーが出た原因をすぐ見たい」** → 2の `%debug`。
* **「特定のループの中を確認したい」** → 3の `breakpoint()`。

特定のコードでエラーが出ていてお困りでしたら、そのコードを教えていただければ、デバッグのお手伝いをすることも可能です。デバッグを試してみたい具体的なコードはありますか？
