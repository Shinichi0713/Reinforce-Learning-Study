目次

    強化学習のタスクで、状態量をLinear層用の列情報として受け取った場合と、CNNで解析できる画像として受け取った場合で前者の方がエージェントは安定して、より良い学習を出来ているようです。

    これは一般的なことでしょうか？

    本日テーマ：

    状態量が画像になった場合、強化学習の安定性や精度に影響を受けることは一般的事実か調べてみた。

    結論

    「Linear層用の状態量（ベクトル）で学習した方が、CNNで画像を扱う場合より安定して良い学習ができる」という現象は、多くの研究で報告されている一般的な傾向のようです。
    以下に、その背景と、それを裏付ける論文・レビューを引用しながら整理します。

    1. 一般的な傾向：ベクトル状態の方が安定しやすい理由

    1.1 情報の密度とノイズ

    • ベクトル状態：
      環境から直接抽出された「意味のある数値」（位置、速度、角度など）が並んでいます。
      → 各次元が明確な意味を持ち、ノイズが少なく、エージェントが学習しやすい。

    • 画像状態：
      画素の羅列であり、多くの画素は「背景」や「無関係な情報」を含みます。
      → エージェントはまず「どこが重要か」をCNNで学習する必要があり、学習が不安定になりがちです。

    1.2 表現学習の負担

    • ベクトル状態：
      状態そのものがすでに「抽象化された特徴」なので、Linear層は単純なマッピング（状態 → 行動）を学習するだけで済みます。

    • 画像状態：
      CNNは「画素 → 特徴 → 行動」という2段階の学習を同時に行う必要があります。
      → 表現学習（feature learning）と方策学習（policy learning）が同時に進むため、勾配が不安定になりやすいです。

    表現学習と方策学習が同時に進むと勾配が不安定になりやすい
    「表現学習と方策学習が同時に進むと勾配が不安定になりやすい」理由は、主に以下の2つの要因によるものです。

    1. 表現と方策の相互依存による「動的ターゲット」問題
    2. 勾配の経路が長く・複雑になること
      1. 表現と方策の相互依存による「動的ターゲット」問題 1.1 表現学習の役割
    • 表現学習（feature learning）は、
      「生の観測（画像など）から、タスクに有用な特徴（feature）を抽出する」役割を持ちます。
    • 例：画像から「物体の位置」「速度」「形状」などの抽象的な特徴を抽出。 1.2 方策学習の役割
    • 方策学習（policy learning）は、
      「抽出された特徴から、どの行動を取るべきか（方策）を学習する」役割を持ちます。 1.3 同時学習の問題点
    • 表現学習と方策学習を同時に行うと、
    • 方策学習は「現在の表現」を前提に最適化されます。
    • しかし表現学習は「表現そのもの」を変えてしまいます。
    • つまり、方策学習のターゲット（最適な方策）が、表現の変化に応じて常に動いてしまう状態になります。 例え：
    • あなたが「今の地図」を見て目的地への最短ルートを覚えようとしている。
    • しかし地図そのものが毎ステップ書き換えられる。
    • すると、覚えたルートがすぐに古くなり、また覚え直さなければならない。
      このように、表現が変わるたびに方策も書き換えが必要になり、学習が不安定になります。 2. 勾配の経路が長く・複雑になること 2.1 勾配の伝播経路
    • CNN＋方策ネットワークのような構成では、
    • 入力 → CNN（表現学習） → 方策ネットワーク（方策学習） → 出力
      という長い経路を勾配が伝わります。
    • 勾配は「出力側の誤差」から逆伝播しますが、
    • 表現層（CNN）のパラメータ更新は、
      「方策側の誤差」と「表現側の勾配」の両方に依存します。 2.2 勾配の不安定化
    • 表現層のパラメータが少し変わるだけで、
    • 方策ネットワークへの入力（特徴）が大きく変わる可能性があります。
    • すると、同じ行動・同じ報酬でも、勾配の向きや大きさが大きく変動しやすくなります。 3. 表現の変化が方策全体に及ぼす影響の大きさ 3.1 表現の「意味」が変わることの影響
    • 表現学習は、
    • 「どの画素が重要か」
    • 「どの特徴が行動決定に効くか」を学習します。
    • 表現が少し変わると、
    • 以前は「重要だった特徴」が無視され、
    • 以前は「無関係だった特徴」が重要になる、
      といったことが起こり得ます。

    1.3 サンプル効率

    • ベクトル状態：
      状態が低次元でノイズが少ないため、少ないサンプルで効率的に学習できます。

    • 画像状態：
      高次元かつノイズが多いため、多くのサンプルが必要になります。
      → サンプル効率が悪く、学習が遅くなり、不安定になりがちです。

    2. 論文による裏付け：State-to-Visual DAgger vs Visual RL

    Mu et al. (AAAI 2025) の論文
    “When Should We Prefer State-to-Visual DAgger Over Visual Reinforcement Learning?”
    AAAI

    では、以下のような比較が行われています。

    2.1 フレームワークの違い

    • Visual RL：
      画像観測（高次元）から直接方策を学習する標準的な強化学習。
    • State-to-Visual DAgger (S2V-DAgger)：
      1. まず低次元の状態（privileged state）で強化学習により教師方策を学習
      2. その教師方策を用いて、画像観測から方策を模倣する（オンライン模倣学習）

    2.2 主な結果（Mu et al., 2025）

    論文では、ManiSkill, DMControl, Adroit など16タスクで比較を行い、以下の点を報告していますAAAI：

    • 漸近性能（Asymptotic Performance）：

      • 「難しいタスク」では S2V-DAgger が Visual RL を大きく上回る。
      • 「簡単なタスク」では両者は同等か、S2V-DAgger がわずかに劣ることもある。

    • 安定性（Stability）：

      • S2V-DAgger は収束後に一貫して安定した性能を示す。
      • Visual RL は性能が揺らぎやすく、場合によっては「学習の後退（unlearning）」も観察される（例：Adroit Pen タスク）。

    • サンプル効率（Environment Steps）：

      • 両者が収束するタスクでは、S2V-DAgger が必ずしもサンプル効率で優位とは限らない。
      • ただし、難しいタスクでは S2V-DAgger の方が「到達できる性能」が高いため、結果的に効率が良いように見える。

    • 計算コスト（Wall-clock Time）：

      • S2V-DAgger はほぼすべてのタスクで、壁時計時間ベースの効率が良い。
      • 理由：高コストな視覚エンコーダの学習が第2段階に限定されるため。

    2.3 推奨事項（Mu et al., 2025）

    論文の結論として、以下のような推奨が示されていますAAAI：

    • S2V-DAgger を推奨するケース：

      • 標準的な Visual RL が苦戦する「難しいタスク」
      • 壁時計時間の効率が重要な場合
      • 高い安定性と一貫した性能が求められる場合

    • Visual RL を推奨するケース：

      • 既に有効であることが知られている「簡単なタスク」
      • 低次元の状態観測（privileged information）が利用できない場合

    この結果は、「まず低次元状態で安定して学習し、その知識を画像方策に転移する」方が、画像から直接学習するより安定しやすいという、ご質問の現象を強く支持しています。

    3. その他の関連研究・レビュー

    3.1 画像ベース強化学習の課題（Chahal, 2021）

    Chahal (2021) の解説記事では、画像ベース強化学習の学習ダイナミクスについて以下のように述べていますMedium：

    • 状態ベースの学習はサンプル効率が高く、安定しやすい。
    • 画像ベースの学習は柔軟性が高いが、多くのデータと計算資源を必要とし、学習が不安定になりがち。

    3.2 医療画像解析におけるRLの限界（Li et al., 2023）

    医療画像解析における強化学習のレビューでは、RLの適用がまだ限定的である理由として、以下の点が挙げられていますPMC：

    • 高次元の画像観測から直接方策を学習するのは難しく、
      多くの場合、教師あり学習や事前学習（pretraining）と組み合わせる必要がある。
    • 状態ベースのRLに比べて、画像ベースRLはサンプル効率と安定性の面で課題が多い。

    4. 実務上の一般的な指針（論文知見を踏まえて）

    1. まずはベクトル状態で試す：

      • 環境から直接抽出できる数値状態（位置、速度、センサー値など）がある場合は、
        まずはそれをLinear層に入力する方が、安定して良い結果を得やすいです。
      • Mu et al. (2025) の S2V-DAgger も、この考え方を体系的に実装したものと言えますAAAI。

    2. どうしても画像が必要な場合だけCNNを使う：

      • ゲーム画面やカメラ画像など、ベクトル化が難しい場合にCNNを検討します。
      • その際は、S2V-DAgger のように「状態ベースの教師方策 → 画像方策の模倣」という2段階アプローチが有効な場合がありますAAAI。

    3. ハイブリッドアプローチ：

      • ベクトル状態と画像状態を両方使う（マルチモーダル入力）こともあります。
      • 例：位置・速度をLinear層へ、周囲の視覚情報をCNNへ、という構成。

    5. 結論

    • 「ベクトル状態＋Linear層」の方が安定して良い学習ができるというのは、多くの強化学習タスクで観察される一般的な傾向であり、Mu et al. (2025) の S2V-DAgger 研究など、近年の論文でも明確に支持されていますAAAI。

    • 一方で、画像そのものが状態である場合や空間構造が重要な場合にはCNNが有利になることもありますが、その場合でも学習の安定化には工夫（2段階学習、模倣学習、事前学習など）が必要です。

    したがって、今回気になっている現象は「一般的な傾向」と言って差し支えないと思います。
    もし画像ではなくベクトル状の状態量が取得できる、かつ、手っ取り早く強化学習の成果を確認したい場合は、やはりベクトル状の状態量を活用した方が良いといえるかと思います。
