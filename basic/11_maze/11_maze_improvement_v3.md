## 現状課題


### モデルの表現力見直し

モデルが少し小さいため、視覚で見えている位置関係から分析できるパターンに制限がかかってる可能性を感じました。ですのでモデルの表現力を見直します。

モデルの表現力はモデルのサイズと置き換えてください。
モデルのサイズにはパラメータが3種類(`num_layers`, `dim_feedforward`, `d_model`)あります。


| 変更 | 何が変わるか | このタスクへの適合度 |
|---|---|---|
| `num_layers` 2→3,4 | 「壁の情報→隣接マスとの関係→さらにその先との関係」という**多段階の関係推論**の深さが増す | 高。迷路の経路探索は本質的に「Aの隣にBがあり、Bの隣にCがあり…」という多ホップの関係を辿る問題。フルAttentionにした今、層を重ねるほど間接的な関係(マスAとマスDの関係、など)をより高次に表現できる |
| `dim_feedforward` d_model×2→×4 | 各トークン（各マス）が個別に持てる非線形変換の表現力が増す | 中。マス単体の特徴表現は5チャンネル(壁/S/G/エージェント/距離)とかなり単純なので、これ以上複雑にする余地は少ない |
| `d_model` 64→96,128 | 全体の次元数が増え、Attentionのquery/key/valueの表現力も上がる | 低〜中。25マス+CLSという小さいトークン数に対し、既に64次元はかなり余裕がある。次元を増やしても、それを活かすだけの多様な入力パターンが少ない |

迷路の探索という問題の本質は「情報の**幅**」より「関係の**深さ**（何ホップ先まで考慮できるか）」なので、層を増やす方が構造的に噛み合っています。

### 迷路の問題で解けなかった問題を集中的に出題
問題の中で得意不得意がありそうな傾向でした。(ゴールが壁に囲まれている場合、ゴール近くをうろうろする、など)
このため、不得意問題を集中的に解かせて苦手な問題への対応力を増すことを考えてみようかと思います。
(これは強化学習の分野で**Prioritized Level Replay**と呼ばれる手法に近い考え方です。)


>__Prioritized Level Replay (PLR)__
>**Prioritized Level Replay (PLR)** は、強化学習（特に手続き型生成環境やマルチタスク環境）において、「エージェントにとって学習価値が高い（＝難しすぎず易しすぎない）レベル（環境のシード値など）を優先的に再学習（Replay）させる」ことで、サンプリング効率と汎化性能を大幅に向上させる手法です。
>DeepMind や NYU などの研究チーム（Minqi Jiang, Jakob Foerster 等）によって提案されました。
>__1. なぜ PLR が必要なのか？（背景と課題）__
>プロシージャル生成（ProcGen）された迷路やミニゲームなどの環境では、ランダムにレベル（シード値）を生成して学習させると以下のような問題が生じます。
>* **無駄なサンプリング**: 易しすぎるレベル（瞬時に解ける）や、難しすぎるレベル（ランダム探索では絶対に解けない）に学習計算リソースを費やしてしまう。
>* **忘却の発生**: 過去にクリアできたレベルや、あと少しで攻略できそうだったレベルの復習機会がランダムサンプリングでは乏しい。
>PLR は、**「すでに経験したレベルの履歴（Level Buffer）」** を保持し、エージェントの現在の習熟度に応じて「今まさに復習すべきレベル」を厳選して提示します。
>__2. PLR の基本アルゴリズムと仕組み__
>PLR の各トレーニングステップでは、一定の確率 $P_{\text{replay}}$（例: 0.5）で動作を分岐させます。
>1. **Replay（復習モード / 確率 $P_{\text{replay}}$）**:
>* バッファ内に保存された過去のレベルの中から、**「スコア（TD誤差など）」が高いレベル**を優先的に選択して再プレイします。
>2. **Unexplored（新規探索モード / 確率 $1 - P_{\text{replay}}$）**:
>* まだ見ぬ完全に新しいシード値（新規レベル）をランダム生成してプレイします。
>* プレイ後のデータ（スコアや軌跡）を評価し、レベルバッファを更新・保存します。
>__3. レベルの優先度（Score）はどう決めるか？__
>PLR の核心は「どのレベルを『優先すべきレベル』とみなすか」です。主に以下の指標（学習プログレスや価値の推定誤差）が使われます。
>* **Value Loss / TD Error（価値関数の予測誤差）**:
>* エージェントが「状態の価値（到達可能性や期待報酬）」を正確に予測できていないレベル。
>* 予測誤差が大きいレベル＝**エージェントがまだ理解しきれておらず、学習の伸びしろ（Learning Progress）が大きいレベル**とみなします。
>* **Max / Mean TD Error**:
>* エピソード内での最大TD誤差や平均TD誤差をレベルの優先度スコアとして設定します。
>__4. 主な派生手法・進化形__
>PLR は単体でも強力ですが、以下のような発展型が存在します。
>* **Robust PLR (R-PLR)**:
>* 過去の評価値（Score）の古さ（Staleness）による偏りを補正し、古くなったレベルのスコアを再評価・更新する機構を備えた堅牢版。
>* **Robust Prioritized Level Replay with Robust Value Learning (Robust PLR / ACCEL)**:
>* **ACCEL (Adversarial Curriculum Through Evolving Levels)** などに発展し、生成型カリキュラム学習（Domain Randomization や 敵対的環境生成）と組み合わせて、難易度を動的に編集・進化させるアプローチへ応用されています。

このため、「毎回完全ランダムな新しい迷路」ではなく、**固定サイズの迷路プールを持ち、そのプール内で正解率が低い迷路ほど出題確率を上げる**、という設計にします。

まず設計を説明します。


__設計方針__

1. **迷路プール**：N個(既定100個)の迷路を保持。各迷路ごとに直近の成功/失敗履歴を記録
2. **出題確率**：`苦手度スコア = 1 - 直近成功率` に比例した確率でプールから選ぶ（不得意なものほど出やすい）
3. **新規迷路の注入**：一定確率でプール外の完全新規ランダム迷路も混ぜる（プール内だけに過学習しないため。苦手な迷路パターン自体を汎化して克服してほしいので、固定10問だけを完璧にする、という状態は避けたい）
4. プールが満杯なら、**最も得意（成功率が高い）迷路を追い出して**新しい迷路と入れ替える

まず`MazeEnv`に「特定の迷路をそのまま設定する」機能を追加します。次に、迷路プールを管理する`MazePool`クラスを新規作成します。次に`transformer_ppo.py`の`train()`にこのプールを統合します。Now train()にプールベースの出題ロジックを追加します。次に、エピソード終了後にプールへ結果を記録する処理と、プールの統計ログを追加します。動作確認します。正常に動作しています(プールが苦手な迷路IDを追跡し、優先的に出題されていることが確認できます)。ファイルを出力します。

__実装__

`MazePool`クラス：
固定サイズの迷路プールを管理し、各迷路の直近成功率から「苦手度スコア（`1 - 成功率`）」を計算、それに比例した確率で出題する迷路を選びます。

`MazeEnv`クラス：
`reset()`に`maze_override`引数を追加。`(maze, start, goal)`を渡すと、ランダム生成をスキップしてその迷路をそのまま再現できるようにしました(プールから取り出した迷路を再出題するために必要)。

`TransformerActorCritic`クラス：
`train()`に`use_prioritized_replay=True`で有効化できるロジックを追加：

- プールが埋まるまで、あるいは確率`pool_new_maze_prob`(既定20%)で新規ランダム迷路を生成してプールに追加
- それ以外は、プールから苦手度に応じた確率で迷路を選んで出題
- エピソード終了後、その迷路の成功/失敗をプールに記録
- ログに**プール全体の成功率**と**苦手Top5の迷路ID・成功率・試行回数**を表示
- `use_curriculum`と併用可能：新規注入する迷路の難易度上限をcurriculumの`current_max_distance`に合わせられます

__使い方__

```python
episode_rewards, success_history = agent.train(
    num_episodes=2000,
    use_prioritized_replay=True,
    pool_size=100,           # プールに保持する迷路の数
    pool_history_len=10,     # 1迷路あたり直近何回分の成功/失敗で判定するか
    pool_new_maze_prob=0.2,  # プール満杯後、新規ランダム迷路を混ぜる確率
)

# 学習後、プールの中身を詳しく見たい場合
print(agent.maze_pool.stats(top_k=10))
```

__注意点・トレードオフ__

- **プールに"べた覚え"するリスク**：`pool_size`が小さすぎたり`pool_new_maze_prob`が低すぎると、その少数の迷路パターンを個別に記憶してしまい、プール外の未知の迷路への汎化が犠牲になる可能性があります。`pool_size=100`程度、`new_maze_prob=0.2`前後から始めて、必要に応じて調整してください。
- **「苦手な迷路」＝「本質的に難しい迷路」とは限らない**：たまたま運悪く数回失敗しただけの迷路も一時的に「苦手」扱いされます。`pool_history_len`を大きめ(15〜20)にすると、ノイズに惑わされにくくなります。
- プール自体は学習経過情報なので保存されません。学習を再開する場合はプールも作り直しになります（必要であれば`pickle`等での保存機能も追加できます）。
